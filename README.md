# Ctrl-F project page

Static site, no build step. Any HTTP server works (videos will not autoplay from
`file://`):

```bash
python3 -m http.server 8765
```

`serve.py` is the same thing plus the cross-origin isolation headers the
simulator needs, for when it is put back on the page.

## The simulator (built, not on the page yet)

The `sim/` folder holds an interactive bench that is not wired into the first
version of the page. Its `bench.js` runs the trained low-level motion-force tracker
inside MuJoCo compiled to WebAssembly. The scene is the hardware gauge test: the
static `raise_hold_static:v0` clip, a cord from the right palm pad to a crane
scale hung from a frame, a tendon-limit force sensor as the scale. Observations
are built exactly as in mjlab's force tracking env (163-D, hands-only layout),
the force command is held in world frame and converted to the symmetric wrist
frame each step, actions go through the same scale and default-offset as
training, control at 50 Hz with four 5 ms physics substeps.

Measured in Python (`sim/bench_py.py --ramp`): 10 / 20 / 30 N commanded gives
6.3 / 15.6 / 24.7 N of cord tension. Hardware read 8.8 / 17 / 25 N.

The WASM build uses pthreads, so the page must be cross-origin isolated. GitHub
Pages cannot send the headers, so `coi-serviceworker.min.js` installs a service
worker that adds them (the first visit reloads once). Locally, `serve.py` sets
the headers directly. Model compilation runs with the spec compiler's
`usethread` off, because the build ships with an empty thread pool and a
threaded compile deadlocks the main thread.

To rebuild the scene after changing the clip or the rig:

```bash
cd sim && python3 build_scene.py
```

To put the bench back on the page: restore the `#demo` section markup and the
`sim/bench.js` module, the three.js import map and the onnxruntime-web script,
and the `coi-serviceworker.min.js` tag in `<head>` (all in git history / the
previous session), and exclude nothing. Without it, `sim/` and
`coi-serviceworker.min.js` can be left out of the deploy.

## Deploying

GitHub Pages works as-is: push this directory to a repo and serve from the root.
Assets total about 70 MB; the largest single file is the 15 MB supplementary
video. `sim/` (31 MB) is not needed by the page and can be left out.
