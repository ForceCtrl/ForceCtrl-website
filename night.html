Abstract

Humanoid motion trackers know where the body should be, not how hard it should act on the world. Ctrl-F adds that missing channel: an explicit 3-D force command at each designated force body, a hand or a foot in our experiments. A motion–force tracker, trained without any object, realises the commanded force while following the reference motion, and a high-level planner chooses the command online from object state and proprioception. On a Unitree G1 this drags, pushes, raises and kicks loads up to 20 kg where a force-blind tracker moves nothing, and the high-level planner adapts its command when the object's mass changes mid-task.

Method

The interface is a reference motion plus a force command. A low-level tracker follows the motion and produces the commanded force at each force body. A high-level planner decides that force.

Stage 1: train the tracker to realise a commanded force

Training has no objects. Each episode samples a 3-D force command for a force body and applies the opposite wrench to it. The only way to hold the reference pose under that wrench is to push back with exactly the commanded force, so the tracker learns the correspondence between a force command and the action that realises it.

The trained tracker under an external force. The hand sinks when only the wrench is applied and recovers once the matching command is given. (0.5×)

On hardware, the commanded force measured on a crane scale. (0.5×)

Stage 2: learn what force to command

With the tracker frozen, a planner reads the object state and the robot's proprioception and outputs one force command per force body. It is trained with an analytical wrench-allocation model as its teacher and refined by reinforcement learning scored on the object's motion. Its command adapts when the load changes.

Mid-task mass change in simulation. Green arrows are the force commands. (0.5×)

Load changes mid-task

Weight is added while the robot is already working. The planner's command follows the load, with no force sensor in the loop.
